# Orizon Nimasa

**Source-labelled ocean and coastal conditions for Nigeria's coast.**

Orizon Nimasa is a mobile-friendly web app that puts marine and weather readings on one dashboard. Every value shows what it is (observed, forecast, model estimate or derived), where it came from, and how old it is. The app also generates rule-based advisories and has a staff console for monitoring data feeds.

It is an **informational tool**. It is not an official forecast, warning, navigation aid or emergency service, and it does not guarantee safe travel or fishing outcomes.

Built with React 18, TypeScript, Vite, React Router, and Leaflet (OpenStreetMap tiles). Tests use Vitest. The product name is Orizon Nimasa, but the npm package is still called `blueintel-nigeria`.

> **Data comes from the API.** Locations, datasets, sources, series, alerts and metadata are all loaded from the FastAPI backend. There is no browser mock mode or hard-coded fallback data. Run the backend and set `VITE_API_BASE_URL` (defaults to `/api/v1`).

## What the app does

### The four design rules

1. **A source on every value.** Each number names its provider and dataset, and links to licence and attribution details.
2. **Time you can check.** Source timestamps are shown in WAT (Africa/Lagos, UTC+1). Data older than its freshness limit is labelled **Stale** and is never presented as current.
3. **Observed is not forecast.** Four badges keep the data types separate: *Observed*, *Forecast*, *Model estimate*, *Derived*.
4. **Gaps stay visible.** Missing readings show as breaks in the chart and as "Missing" in the table. Nothing is interpolated or invented.

### What you can see and do

**Public website** (`/`, `/about`, `/feedback`)
- **Landing page:** a live snapshot for the selected location, the four rules above, sources under review, and a "what this tool is not" notice.
- **About & limits:** product principles, what the tool does not do, and the privacy position.
- **Pilot feedback:** a short optional form (found what you needed? was the source and time clear? free-text comments).

**Public dashboard** (`/dashboard`, `/alerts`, `/sources`, `/insights`, `/marine`, `/developer`)
- **Dashboard**
  - **Latest values** for every dataset returned by `/datasets`. Each has a type badge and a freshness badge.
  - **Map room:** an interactive Leaflet map with one colour-coded layer per dataset. Markers and coverage bounds are derived from `/locations`; values are shaded using a colour ramp derived from the loaded series.
  - **Trend chart** with 24 h / 48 h / 7 day ranges, forecast styling, visible gaps and the configured advisory threshold.
  - **3-day outlook** and a **plain-language summary** generated by a fixed rule, not by AI.
  - **Export** the chart as CSV, PDF, PNG or JPG through the backend.
- **Alerts:** location-based advisories from `/alerts`, filterable by location and type. Each alert shows the trigger, data type, source, source time, issue time and validity window. The configured rule table comes from `/alert-rules`.
- **Data sources:** sources and datasets from `/sources` and `/datasets`, including licence, attribution, refresh interval and stale-after limits.
- **AI insights:** a grounded, source-cited question interface. It works when the backend has a model key; otherwise it shows a clear unavailable state and the rest of the app keeps working.
- **Marine layers:** AIS vessel positions and 48-hour tracks, bathymetry points and tide predictions from the API.
- **Developer portal:** self-service sandbox keys, cURL/JavaScript quickstart recipes and live quota usage.

A red **alert ticker** runs across the dashboard and also reports data-quality problems (stale feeds, service unavailable, no data yet).

**Staff operations console** (`/admin/login`, `/admin`)
- Application health and data-feed health, reported separately.
- Feed freshness per location and dataset.
- Recent ingestion runs (source, outcome, records accepted and rejected, error category).
- Full CRUD for alert rules, locations, sources, datasets, notification targets, API keys and staff (role-aware: admin / operator / viewer).
- Data-quality summary, durable job queue, notification outbox and full audit trail.
- Two-factor authentication (TOTP), password change and password reset.
- Run ingestion now and per-source enable/disable controls.

The app is also installable as a PWA-style home-screen app (web manifest, starts at `/dashboard`).

## Quick start

Requires Node.js 18 or newer and a running Orizon Nimasa API.

```bash
npm install
npm run dev        # http://localhost:5173 (Vite picks the next free port if busy)
npm test           # 5 unit tests for the freshness policy
npm run build      # type-check, then production build into dist/
npm run preview    # serve the production build locally
```

To pin the dev port: `npm run dev -- --port 5133`.

### API configuration

The client always calls the API. `VITE_API_BASE_URL` defaults to `/api/v1`, which the Vite dev server proxies to `http://127.0.0.1:8015`.

| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Backend base URL. Defaults to `/api/v1`. Set a full URL to call the API directly. |
| `VITE_API_PROXY` | Proxy target when using `/api/v1` (default `http://127.0.0.1:8015`). |
| `VITE_TILE_URL` | Basemap tile URL (default: public OpenStreetMap server). |
| `VITE_TILE_ATTRIBUTION` | Attribution text shown under the map and in the footer. |
| `VITE_API_DOCS_URL` | Optional API documentation URL used by the insights page. |

No secrets belong in this client. Provider API keys live on the backend only.

## Backend endpoints the client calls

Base path `/api/v1`.

| Area | Endpoints |
|---|---|
| Data | `GET /locations`, `/datasets`, `/sources`, `/series`, `/summaries`, `/locations/{id}/summary` |
| Alerts | `GET /alerts`, `/alert-rules` |
| Export | `GET /locations/{id}/series.{csv,png,jpg,pdf}` |
| Feedback | `POST /feedback` |
| Insights | `POST /insights/query` |
| Health | `GET /health` |
| Marine | `GET /vessels`, `/vessels/{mmsi}/track`, `/bathymetry`, `/tides` |
| Developer | `POST /developer/keys`, `GET /developer/usage`, `DELETE /developer/keys/current`, `GET /developer/recipes` |
| Admin (bearer token) | Auth, feeds, rules, locations, sources, datasets, staff, API keys, notifications, jobs, quality, audit and ingestion trigger |

`client.ts` adapts the API's snake_case/ISO responses to the UI's `Bundle`, `Series`, `AlertEvent` and metadata shapes. Freshness is computed in the UI from `source_timestamp` and each dataset's `stale_after_minutes`.

## Known limitations

- **Data quality depends on the configured backend sources.** The development seed uses a synthetic source; the UI labels whatever source metadata the API returns. Replace it with an approved provider before any pilot.
- **Alert thresholds are configured on the backend** and should be reviewed by a qualified marine or meteorological specialist before operational use.
- **AI insights need a backend model key.** Without one the page shows an explicit unavailable state; the rest of the app is unaffected.
- **Marine feeds may be demo or provider-backed.** Check the source metadata returned by the API before navigation use.
- **Coverage area and indicators are configuration, not constants.** Locations and datasets come from the API and can be changed in the operations console.
- **English only.** Language support will follow discovery.
- **Basemap:** the public OpenStreetMap tile server has usage limits. Choose a tile provider before launch.
- **Privacy:** the public site collects no personal data, but a full privacy notice and a Nigerian data-protection review are required before production.

## Deployment

`npm run build` produces a static site in `dist/`. Configure your host with an **SPA fallback** so deep links such as `/alerts` and `/admin` serve `index.html`. Set the `VITE_*` variables at build time, since Vite inlines them.

## Project structure

```
src/
  App.tsx             route table (public site, dashboard, admin login, admin)
  config.ts           app name, timezone, map tiles, labels, colour ramp
  types.ts            shared types (Series, Point, AlertRule, AlertEvent, ...)
  api/
    client.ts         FastAPI client + response adapters
  context/
    DataContext.tsx   loads metadata and series, computes freshness, polls the API
    AuthContext.tsx   admin sign-in with a bearer token
  layouts/            PublicLayout (website), DashboardLayout (sidebar), AdminLayout
  pages/              Landing, About, Feedback, Home (dashboard), Alerts, Sources,
                      Insights, Marine, Developer, AdminLogin, AdminLive
  components/         MapView, TrendChart, AlertTicker, Sidebar, Topbar, Footer,
                      Badges (type/freshness), States (loading/empty/error)
  lib/                freshness, geo, time
  __tests__/          Vitest tests for the freshness policy
public/               icons and web manifest
```
